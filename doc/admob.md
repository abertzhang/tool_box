# AdMob 广告类型与收益优化手册

> 适用对象：tool_box（Tirope 工具箱）Flutter 工程
> 整理时间：2026-09-17
> 数据来源：Google AdMob 官方帮助中心 + 2026 年第三方变现基准报告
> ⚠️ 文中 eCPM 区间为**第三方统计的参考值**，非 Google 官方承诺，仅用于量级判断与决策排序。

---

## 一、六种广告类型总览

AdMob 目前提供 6 种广告格式。它们的本质区别只有三件事：**占不占整屏**、**用户是否主动选择**、**奖励是否必须发放**。

| 格式 | 展示形态 | 用户选择权 | 典型 eCPM 档位 | 干扰度 | 适合位置 |
|---|---|---|---|---|---|
| **Banner** 横幅 | 占版面一部分，可自动刷新 | 无（被动曝光） | 最低（~$0.3–1.5） | 低 | 工具页底部常驻 |
| **Interstitial** 插页 | 整屏，自然过渡点弹出 | 只能关闭 | 中高（~$5–14） | 高 | 页面/关卡切换处 |
| **Rewarded interstitial** 插页式激励（Beta） | 整屏 + 奖励 | 有介绍页，可退出 | 高 | 中高 | 自然过渡点 + 奖励 |
| **Rewarded** 激励 | 整屏 + 奖励 | **必须主动 opt-in** | 最高（~$14–22） | 最低（因为自愿） | 明确的权益兑换 |
| **Native advanced** 原生高级 | 与 App UI 融合，内联 | 无（被动曝光） | 中（远超 banner） | 低 | 信息流 / 列表 |
| **App open** 开屏 | 整屏，App 进入前台时 | 只能关闭 | 中高 | 高（易流失） | 冷启动 / 回前台 |

**eCPM 的底层逻辑**：广告主只为「确定会被看到、且看到的人有购买意图」的展示付钱。
激励广告 eCPM 最高，是因为用户是**主动选择观看**的，完成率和注意力都远超被动曝光；
Banner 最低，是因为它长期挂在屏幕上，用户早已学会无视（banner blindness）。

## 二、逐格式详解与最佳实践

### 1. Banner（横幅）

**定义**：占据版面一部分的矩形广告，可在一段时间后自动刷新。

**实践要点**
- 用 **自适应横幅（Adaptive Banner）** 而不是固定 320×50 —— 它按设备宽度自适应，收益高 20–40%。
- 2026 年新增 **大号锚定自适应横幅（Large Anchored Adaptive Banner）**，高度约为标准版两倍，面向现代大屏设备。本项目已在用（`banner_ad_view.dart` 中的 `getLargeAnchoredAdaptiveBannerAdSize`）。
- 锚定（anchored，固定顶/底）一般优于内联（inline，插在内容流中间）。
- **300×250 中矩形（medium rectangle）** 收益是普通横幅的 4–7 倍，适合放在暂停页、内容间隙；但**绝不能放在导航流程中**。
- 底部锚定时要与系统手势条/返回键保持安全距离，否则误触会被判「鼓励误点击」违规。
- 自动刷新间隔不要太激进（建议 ≥ 30s，默认 60s）。刷新过快既伤体验又拉低单价。

**红线**
- 不得与可点击元素重叠或紧邻（建议与内容留 ≥ 5px 间隔，最好有边框/底色分隔）。
- 不得夹在两段内容之间、不得插在导航栏与内容之间。
- 不得浮在内容之上（广告区必须是独立高度，不与应用内容上下重叠）。

### 2. Interstitial（插页）

**定义**：整屏广告，出现在自然中断与过渡点（如关卡完成）。

**实践要点**
- **只在内容切换的瞬间展示**：页面 A → 页面 B 的转场处。
- **必须预加载**：触发前就 load 好，避免网络延迟导致广告晚于转场弹出（这是「意外点击」最常见的成因）。
- **频次上限**：用户每 2 次操作最多展示 1 个插页；不能在刚关闭一个插页后立刻弹下一个。
- 屏幕必须有「不用点广告也能退出」的路径（返回/菜单按钮）。

**红线**
- **禁止**在 App 启动时（点图标后立刻）或退出时展示 —— 那两个场景归开屏广告/退出确认弹窗。
- **禁止**在用户专注操作时（填表、阅读、游戏中）突然弹出。
- **禁止**在后台或应用环境之外投放。
- 点击按钮后弹出插页、关闭后还停在原页面 —— 这种场景不适合插页，应改用激励广告。

### 3. Rewarded interstitial（插页式激励，Beta）

**定义**：在自然过渡点给予奖励的整屏广告。与 Rewarded 的区别是**用户无需提前 opt-in**，但必须有一个**清晰无遮挡的介绍画面**，说明奖励内容、并留出足够时间让用户理解与**主动退出**。

**实践要点**
- 介绍画面（intro screen）必须：清楚说明奖励、不被遮挡、给出明确的退出选项。
- 适合场景：标准插页显得太粗暴、但纯被动的激励位又没人点的中间地带。
- 因为是 Beta 且政策更细（既受插页规则约束、又受激励规则约束），**新接入建议优先用 Rewarded**，等主流程跑顺再评估它。

### 4. Rewarded（激励）

**定义**：用户**主动选择**观看，看完获得奖励的整屏广告。与插页式激励的区别是用户必须 opt-in。

**实践要点（本项目已在用）**
- **只在 `onUserEarnedReward` 回调触发时才发奖** —— 这是本项目 `rewarded_ad_helper.dart` 的核心设计：`shown`（播过）与 `earned`（走到奖励回调）拆成两个布尔，中途退出时 `shown=true / earned=false`，**不发奖**。
- **奖励必须即时发放**：看完立刻到账，不能延迟或不可兑换。
- 触发按钮必须让用户有明确预期：标注「广告」标识，并写清「看一次得 X 次」。
- 奖励价值要能真正推动核心循环 —— 太弱的奖励没人看，太强的奖励会侵蚀付费转化。
- 预加载，避免点击后等待。
- 用 A/B（Firebase Remote Config）试验奖励数量，找到收益与付费侵蚀的平衡点。

**红线（激励广告通用政策）**
- 必须**逐个**选择观看，不允许"自动连续观看"。
- 奖励只能在发布者与用户之间交易，Google 不授予也不验证奖励。
- **不得**用「支持我们」「帮帮开发者」这类话术诱导 —— 只能陈述客观奖励。
- **不得**在提供货币/可变现补偿（礼品卡、折扣、加密货币）的用户流中投放。
- **不得**承诺奖励却不发放、或延迟发放。
- 随机奖励可以，但必须公示概率。
- **不得**用插页的展示逻辑来呈现激励广告（即不能自动弹）。

### 5. Native advanced（原生高级）

**定义**：可自定义、与 App 观感一致、内联在内容中的广告。

**实践要点**
- 用代码自己渲染（标题/图片/CTA 等由你排版），能做到与 UI 完全融合，CTR 与用户好感都优于横幅。
- 适合信息流、文章列表、市场/商城、内容流。
- 广告背景必须**不可点击**（不含可点击的"空白区域"）。

**红线**
- 必须有明确的「广告 / Ad / 赞助」标识。
- 尺寸不得小于 32×32dp(Android) / 32×32pt(iOS)。
- 主视觉（视频/大图）必须用官方 `MediaView` 渲染。
- 广告元素之间不得重叠、不得与功能按钮距离过近。
- 不得用诱导性动效（扫光、跳动按钮）吸引点击。

### 6. App open（开屏）

**定义**：用户打开 App 或从后台回到前台时展示的整屏广告。

**实践要点**
- **只在「进入 / 回到前台」这一个场景使用**，其他位置改用插页。
- 必须配合加载态（loading screen），给广告留出加载时间。
- **严格限频**：不要在用户每次切回来都弹；建议只在满足一定间隔（如 ≥ 4 小时）且用户此前已真正使用过 App 时展示。
- 对高频打开的品类（工具、社交）收益可观，但也是**流失风险最高**的格式 —— 冷启动秒开却弹广告，是典型的负面体验。

**红线**
- **不得**在退出 App 时展示（退出时不应展示任何全屏广告）。
- **不得**挪用到非"进入/回前台"的场景。

## 三、如何选型：按场景决策

```
用户是主动想要某个权益吗？
├── 是 → Rewarded（激励）        ← eCPM 最高、体验最好
└── 否
    ├── 是 App 进入 / 回前台吗？
    │   └── 是 → App open（严格限频）
    ├── 是内容/页面的自然转场点吗？
    │   ├── 是 → Interstitial（预加载 + 限频）
    │   └── 否 → 页面有信息流/列表吗？
    │       ├── 有 → Native（融合 UI）
    │       └── 无 → Banner（底部锚定自适应）
```

**按品类侧重的格式组合**

| 品类 | 首选 | 次选 |
|---|---|---|
| 游戏 | Rewarded | Interstitial |
| 工具 / 实用 | Banner 或 Native | Rewarded（解锁额度） |
| 内容 / 媒体 | 信息流 Native | 转场 Interstitial |
| 效率 / 金融 | 混合变现为主，广告极克制 | — |

**tool_box 属于工具品类**，合理组合是：**Banner 打底 + Rewarded 换权益 + 严格限制的 App open**。插页在工具 App 里要慎用 —— 工具类用户是「拿来就用一个功能就走」，插页打断感极强，容易换来一星评价。

## 四、提升回报的核心杠杆

收益的基本公式：

```
日收入 = DAU × 人均展示次数 × eCPM ÷ 1000
ARPDAU = 日收入 ÷ DAU
```

三个乘数里，**eCPM 的弹性最大，但最容易改错的也是它**。按性价比排序的杠杆：

### ① Mediation（中介）+ Open Bidding —— 收益提升 18–35%

只用 AdMob 单网，会把 **15–25% 的收益留在桌上**。接入中介（AppLovin MAX / ironSource LevelPlay / Google 自己的 bidding）让 Meta、Vungle、Pangle、Mintegral 等在同一场竞价里抢量，30 天内通常能看到 ARPDAU 提升 18–22%。

- **实时竞价（bidding）优于传统瀑布流（waterfall）**：竞价把每次展示都拿去实时拍卖，省掉瀑布流的顺序损耗，首个结算周期常能带来 20–35% 的 eCPM 提升。
- 实操：bidding 与 waterfall **并行跑 14 天**比对差值，再全量切换。
- **门槛**：通常 MAU 过 5 万才值得上中介；之前用 AdMob 单网最快、最省事。

### ② 地域与用户分层 —— 最大单一变量

eCPM 地域分档（以美国为 1.0）：

| 档位 | 市场 | eCPM 指数 | 全球安装占比 |
|---|---|---|---|
| Tier 1 | US/CA/UK/AU/DE/JP | 0.75–1.00× | ~20% |
| Tier 2 | FR/IT/ES/KR/PL/SA/AE | 0.35–0.60× | ~25% |
| Tier 3 | IN/ID/BR/PH/NG/PK/VN | 0.05–0.18× | ~55% |

**这解释了一个常见困惑**：DAU 翻了 3 倍，收入几乎没动 —— 因为新增的是 Tier 3 流量。不要只看 DAU 做决策。

### ③ 频次：不是越多越好

- 用 A/B 测 2 / 3 / 5 次每 session 三档，在同等用户群上跑。
- **多数情况下 3 次/会话 的月总收入高于 5 次/会话** —— 因为 30 日留存保住了，整月总展示量反而更大。这是个「少即是多」的典型。

### ④ 混合变现（IAP + 广告）

- 头部非游戏 App 里超过一半是 **IAP + 广告并行**。
- 付费用户 LTV 是纯广告用户的 **8–15 倍** → 给付费用户**降广告量**，让广告收入去承接非付费用户。
- 本项目已有会员体系（Pro）+ 免费次数 + 看广告换次数，正是这个模型，方向正确。

### ⑤ 底价（Floor Price）月度调优

- 填充率 > 90% 说明底价低于市场价 → 每次上调 10–15%，每个测试至少观察 72 小时（覆盖日内需求波动）。
- 目标区间：**填充率 75–85%**，此时优质需求占主导、总收益最高。
- 反向操作：收入下滑时，降低底价能赢回更多竞价，扩大出价覆盖面。

### ⑥ 同意率（Consent）—— 被严重低估的杠杆

- **未拿到同意时，AdMob 只能填非个性化广告，单价低 60–80%。**
- EU/UK 必须接 UMP SDK（TCF v2.2）；iOS 14.5+ 走 ATT。
- 好的同意话术能把同意率做到 70%+；ATT 前置解释页能把授权率从 35–45% 提到 55–70%。
- **这一项的收益往往超过你今年做的任何一次广告位实验。**

### ⑦ 屏蔽控制与广告类别

- 每屏蔽一个类别，就少一批广告主竞价 → eCPM 下降。**尽量少屏蔽**，只停具体子类别。
- 启用全部广告类型（文字/图片/视频）能吸引更多广告主，抬高 eCPM。

### ⑧ app-ads.txt（合规硬要求）

- **2025 年 1 月起，所有新应用必须实施 app-ads.txt**，未合规会被**限流（广告投放被节流）**。
- 做法：在 AdMob 控制台拿到发布商 ID 与文件内容，托管到你的域名根目录，并在商店列表填 App 的开发者网站。

### ⑨ SDK 延迟与稳定性

- 盘点中介栈里每个 SDK 的冷启动耗时，**超过 1.5s 的降级或替换**。
- 延迟 > 2s 会在第一个广告加载前就流失 24% 的首会话用户。

## 五、政策红线与常见违规（务必自查）

Google 把违规分为 5 类，后两类是工具和中小开发者最容易踩的：

| 类别 | 后果 | 典型触发 |
|---|---|---|
| 1. 明确违规 | 必须整改 | 露骨内容、危险/诋毁内容、布局诱导点击 |
| 2. 发布商限制 | 变现受限 | 色情、惊悚、在线赌博内容 |
| 3. 警告 | Play 应用被停用 | 广告与内容重叠、不允许的激励手段 |
| 4. 确认点击 | 强制二次确认 | 广告紧邻导航元素、按钮位于广告上/附近 |
| 5. 用户意见征求 | 变现受限 | EU/UK 用户未接 CMP |

**高频踩坑清单**

- **鼓励误点击**：原生/Banner 与内容无明显分隔 → 用边框或底色区分，留 ≥ 5px 间距。
- **原生广告空白区域可点击** → 只有图标/标题/图片/按钮可响应。
- **广告放在导航列表内或紧邻** → 明确违规。
- **无价值页面放广告**（如"关于我们"）→ 会被判"网站行为：导航"受限。
- **激励视频代替插屏使用**：激励必须由用户主动触发，不能自动播放（虽然激励 eCPM 更高，但这样用是违规）。
- **激励按钮无「广告」标识 / 未标明奖励内容** → 违规。
- **点击核减**（点击率突然接近 0、eCPM 同步下滑）：多因流量质量异常（非商店流量、离线安装、非真人）、或改版后出现异常高频点击。按渠道/位置/版本拆分打点排查。
- **无效流量（IVT）**：点击注入、SDK 作弊、激励安装、模拟器/机器人流量。被判定后 eCPM 掉 30–50%，**恢复需 6–12 周**。
- **绝对不要**用真 ID 反复请求自家广告，也不要点自家广告 —— 这是独立开发者被封号最常见的原因。

**一条生存法则**：永远不要试图挑战平台明确说明的底线。被封号时平台不会打招呼，且历史待付收入会被没收。

## 七、速查表：一次记住

```
收益排序：Rewarded > Interstitial > App open ≈ Native >> Banner
风险排序：App open > Interstitial > Rewarded interstitial > Native > Banner > Rewarded

三条铁律：
1. 广告只在"用户预期到"的时刻出现 —— 启动/退出/操作中途都是禁区
2. 奖励只在 onUserEarnedReward 触发后发放，且必须即时到账
3. 合规优先于收益 —— 被限流/封号的代价远大于优化带来的增量

最大的三个杠杆（按性价比）：
① 同意率（非个性化广告单价低 60-80%）
② 地域结构（Tier1 与 Tier3 差 6-20 倍）
③ Mediation + 实时竞价（+18~35%）
```

## 八、激励广告填写

### 具体内容

| 字段                         | 推荐填法                                         | 理由                                                         |
| ---------------------------- | ------------------------------------------------ | ------------------------------------------------------------ |
| **Ad unit name**             | `Rewarded_<平台>_<用途>`，如 `Rewarded_iOS_复活` | 命名要能一眼看出格式 + 平台 + 场景，方便后续多个广告单元管理 |
| **Partner bidding**          | **不要勾选**                                     | 只有当你同时用其他聚合平台（MAX、TopOn 等）做实时竞价时才勾选。勾选后**不可更改**，且该单元不能再用于 AdMob 中介 / Google Ads 需求。多数情况下用 AdMob 中介就够了 |
| **Reward item**              | 游戏内货币 / 道具名，如 金币、宝石、生命、提示   | 必须是玩家认可价值的虚拟物品                                 |
| **Reward amount**            | 适中值，常见 5～50 个货币单位                    | Google 官方核心建议：**不能高到冲击内购（IAP），但要足够吸引人看广告**。示例游戏给 5 颗宝石，需要更多就得内购 |
| **Ad type**                  | Video                                            | 视频填充率最高、最稳定；Interactive（可玩广告）更适合重度游戏场景，初期建议 Video |
| **Server-side verification** | **强烈建议开启**                                 | 防止客户端伪造回调白嫖奖励，保护游戏经济。需后端接收并验证 SSV 回调（Google 推荐客户端先即时发奖 + 服务端校验兜底） |
| **Frequency capping**        | 保持 **Disabled**                                | 激励广告是用户主动选择观看，过度频控反而压低收益；如担心刷量可后续加 "每人每日上限" |
| **eCPM floor**               | **Google optimized + All prices（起步）**        | Google 动态底价最省心；"All prices" 最大化填充率，先跑数据。等积累 30 天数据后再考虑 Medium/High floor |

### "最有效" 的组合策略

1. **起步期（前 4 周）**：`Google optimized + All prices`。这个阶段目标是**把填充率拉满、把数据跑出来**，低 eCPM 地区的填充问题优先解决。

2. 稳定期（有 30 天数据后）

   ：

   - 如果**填充率很高但 eCPM 偏低** → 切 `Medium floor`（平衡高价广告与填充率）；
   - 如果**填充率健康且想冲收入** → 试 `High floor`（最大化高价广告，但填充率会降，需观察）；
   - 参考基准：美国区激励视频 eCPM 中位数约 $8–$18，可用近 30 天平均 eCPM 的 **60–70%** 作手动底价的参考线。

3. **奖励值做实验**：奖励金额别一次定死，建议用 A/B 实验对比 "5/10/20 货币" 的观看率与 IAP 影响，找到平衡点。

### 两个易错点提醒

- **奖励过高**会直接吃掉内购收入，是激励广告最常见的错误；**过低**则用户不愿看，两头都不讨好。
- 上线后要持续盯 `匹配率`（match rate）和 `填充率`：如果匹配率低，先确认 app-ads.txt 已配置、底价没设过高。
