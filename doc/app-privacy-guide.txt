Tool Box — App Privacy 隐私问卷操作指引（逐步）
=================================================
日期：2026-09-27
依据：项目代码实际收集的数据（账号体系 / Supabase / AdMob / 埋点 / 设备ID哈希）
适用：App Store Connect → App 隐私（App Privacy）问卷
目的：如实填写，避免「问卷与实际不符」被拒

====================================================================
一、问卷入口与总体原则
====================================================================
位置：App Store Connect → 你的 App → 定价与销售范围左侧「App 隐私」→ 开始回答
原则：
1. 如实勾选 App 实际收集的数据，宁多勿漏（漏填被查到会被拒/下架）。
2. 「收集」= 数据离开设备被你的服务端获取。本地 Isar/清单/备忘录不上传 → 不勾。
3. 勾选后需填写：数据用途、是否关联身份、是否用于追踪。

====================================================================
二、数据收集类型（逐项勾选，按你的项目）
====================================================================
进入问卷后，按顺序做以下勾选：

【第 1 步】是否收集数据 → 选「是」（你的 App 确实收集了下列数据）。

【第 2 步】勾选以下数据类别（出现一个勾一个）：
□ 联系信息 → 邮箱地址          （登录账号 email，Supabase users 表）
□ 联系信息 → 姓名                （昵称 displayName，编辑资料可填，最长24字）
□ 标识符 → 用户 ID               （auth.users.id / public.users 主键）
□ 广告数据 → 投放相关数据        （AdMob 展示/点击，App 内投放广告）
□ 其他数据 → 其他诊断数据        （埋点 app_events：页面浏览、工具使用、错误等）
□ 其他数据 → 其他数据类型        （设备标识：IDFV/ANDROID_ID 的 SHA-256 哈希）

不勾选的类别（你的 App 不收集这些）：
✗ 购买记录        —— 内购仅本地 StoreKit 校验，云端不写支付信息（方案A）
✗ 位置            —— 指南针仅本机读取 GPS 海拔/经纬度，不上传
✗ 用户内容        —— 出行清单/备忘录存本地 Isar，不上传、不分发
✗ 搜索历史 / 浏览历史 / 诊断-崩溃数据(如无单独上报)
✗ 广告标识符(IDFA) —— Info.plist 无 NSUserTrackingUsageDescription，不请求 IDFA

====================================================================
三、每个勾选项的必填字段（逐个类别填写）
====================================================================
对每个勾选的数据类别，回答三个问题：

1) 该数据是否与用户身份关联？
   - 邮箱 / 姓名 / 用户ID   → 是（登录用户，存于 public.users）
   - 诊断/埋点数据          → 是（登录后带 userId；未登录游客为 null，部分匿名）
   - 其他-设备标识(哈希)    → 是（用于游客免费次数，绑定设备）
   - 广告数据               → 否（AdMob 匿名投放，与账号无直接关联）

2) 该数据是否用于追踪用户？
   - 广告数据 → 是（AdMob 投放涉及广告追踪）
   - 其余 → 否（不跨 App/不用于广告画像定位）

3) 该数据用途（用途勾选）：
   - 邮箱/姓名/用户ID → 账号功能（登录、资料展示）
   - 诊断/埋点        → App 功能、分析、产品改进
   - 设备标识(哈希)   → 防滥用 / 产品个性化（免费额度绑定设备）
   - 广告数据         → 第三方广告投放

说明：未登录游客也会上报「匿名埋点」与「哈希设备ID」用于免费额度，
      若问卷询问是否对未登录用户收集，如实填「是」并注明匿名。

====================================================================
四、广告与追踪联动项（重点，别漏）
====================================================================
1. 你的 App 接入 AdMob 广告 → 必须在「广告数据」如实勾选。
2. 由于你不请求 IDFA（无 NSUserTrackingUsageDescription），
   「标识符 → 广告标识符(IDFA/IDFV)」这一项可只勾 IDFV 哈希部分或按实际，
   IDFA 不要勾（你没申请）。
3. 年龄分级问卷「是否包含广告」→ 选「是」（banner/激励/插页）。
4. 不要勾选「专为儿童设计」——否则 COPPA 会禁用 AdMob 广告。

====================================================================
五、隐私政策 URL（问卷要求提供）
====================================================================
填写你 Github Pages 的隐私政策页链接（可公开访问）：
https://aberciozhang.github.io/privacy/tool-box?type=1
（或你自建的 aknot.uk 对应页）
确保隐私政策正文与本次问卷勾选一致：写明收集邮箱/昵称/用户ID/埋点/
哈希设备ID、使用 AdMob 广告、账号注销删除数据方式。

====================================================================
六、提交前自查清单
====================================================================
[ ] 数据收集 → 是
[ ] 已勾选：邮箱、姓名、用户ID、广告数据、诊断/埋点、设备标识(哈希)
[ ] 未勾选：购买记录、位置、用户内容、IDFA
[ ] 每个勾选项已填：是否关联身份 / 是否用于追踪 / 用途
[ ] 广告数据勾了「用于追踪」
[ ] 年龄分级广告项填「是」，且未勾「专为儿童」
[ ] 隐私政策 URL 已填且可访问，内容与问卷一致
[ ] 完成后点「保存并完成」，状态变为「填写完成」

====================================================================
七、与主审核回复的一致性提醒
====================================================================
主审核回复（app-review-response-en.txt）中：
- 第4点 External services used 已写明 Supabase + AdMob + Apple/Google 登录；
- 隐私问卷勾选的类别必须与这份描述互相印证，避免前后矛盾被追问。
